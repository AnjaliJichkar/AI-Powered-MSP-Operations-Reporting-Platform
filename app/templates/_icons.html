{# The icon set, from the Aurora mockup. One path per name, drawn in a 24-unit square with no fill and a 1.6 stroke in `currentColor`, so an icon takes the colour of whatever it sits in — muted in the nav, the accent on the page you are on, ink in a menu — and nothing needs a second copy per theme. There is no build step and there is not going to be one, so an icon font or a sprite pipeline is out: an icon is markup. `aria-hidden` on every one of them. An icon never carries meaning on its own: every nav entry has its label beside it or, narrowed, clipped off screen where a screen reader still reads it, and every control has a name. **A name that is not here draws `missing`, and never another real icon.** It fell back to the sparkle once, which printed the same glyph on every row of the nav with no error anywhere; then it fell back to nothing, which drew an empty 18px square — and an empty square at nav size is not a question somebody asks, it is a nav with no icons at all, which is how the same fault was reported twice. `missing` is a crossed box: unmistakably not a drawing anybody chose, and impossible to overlook. The loud half is `assert_icons_named` in `app/interfaces/web.py`, which refuses to build the application when a nav entry names a drawing this file does not have. It cannot help a *running* process whose Python is older than its templates, which is exactly how an empty nav survives a restart of the wrong server — so the quiet half has to be visible. #} {#
